Course Objectives

Three objectives for CSC102, and the page on this site that shows I hit each one.

1Demonstrate basic formal problem-solving techniques for programming

Every interactive page here started as a problem written out in plain language before any code got typed. The palindrome checker is the clearest example: strip the punctuation and the spaces, force everything to lower case, reverse the copy, compare it to the original. Four steps, decided before I opened the editor.

This is the same order I worked in for thirty years as an electrician. You do not start pulling wire until you know where the circuit runs.

Evidence: Palindrome Checker and Award Guess Game

2Describe and apply variables, basic and composite data types, and collections

The game page holds a target number and a guess count in number variables and a running result in a string. The meme page keeps its three memes in an array of objects, which is a collection of composite values, and reads the one the user picked out of it by index. The application form works with strings, a number, and a Boolean flag that tracks whether every field passed.

Evidence: Meme Wall and Application Form

3Demonstrate effective troubleshooting, testing, and debugging of programs

Every page on this site loads with a visible placeholder message that the JavaScript file overwrites when it runs. If I open a page and the placeholder is still sitting there, the script never loaded, and I go check the file name and the path before I go hunting anywhere else. That is a deliberate test point, not an accident.

Validation gets tested the same way I tested circuits: feed it the bad input on purpose. An empty name, an email with no @ sign, a negative award amount, a decimal where a whole number belongs. If the form accepts any of those, the check is broken.

Evidence: Application Form and Grant Table

Inline vs Internal vs External CSS

External is styles.css. Every page links to it and it holds anything used more than once. One edit changes the whole site.

Internal is a <style> block in the head of a single page. The welcome band on the home page and the score panel on the game page are written that way, because neither is used anywhere else.

Inline is a style attribute on one element. It overrides the other two because it is the most specific. It is on the About box on the home page and on the intro line of the grant table. It is the least maintainable of the three, so I kept it to those two spots on purpose.
